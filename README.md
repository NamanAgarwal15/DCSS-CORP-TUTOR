# Corporate Startup Tutor

An AI Agent Tutor web app for university entrepreneurship courses. Each student
group gets a shared, passcode-protected dashboard where they record class
reflections, curate fortnightly corporate-startup news updates, and keep a
running log of notes — all visible to faculty.

Built with Next.js, Prisma/Postgres, and Google Gemini.

## Features

- **Group dashboards** — create a group with a passcode (min 6 characters) and
  share the `/group/<slug>` link plus the passcode with group members. The
  passcode is asked once per browser; only a salted scrypt hash is stored.
- **Class Reflection** — the group writes (1) a summary of what was covered in
  class and (2) one question they couldn't get clarified. Gemini turns the
  summary into 3–5 key points; the open question is stored exactly as the
  group wrote it (never generated by the model).
- **Fortnightly News Update** — its own paste box; two modes via `NEWS_MODE`:
  - `grounded` — Gemini searches the web with Google Search grounding.
  - `manual` (default) — students paste news content; Gemini structures it into
    source / summary / why-it-matters entries, labeled *manually curated*. A URL
    is kept only if it appears verbatim in the pasted text, and only `http(s)://`
    URLs are rendered as links.
- **Student notes** — free-form notes in the group history (no AI call).
- **Conversation-style history** — each AI interaction shows the students'
  message, then the tutor's card, with the raw AI response expandable beneath;
  notes appear inline in time order.
- **Faculty area** — `/faculty/login` (credentials from env vars) → `/faculty`
  lists every group with entry counts. Faculty can open any group without its
  passcode.
- **Append-only** — nothing is edited or deleted through the app.

## Tech stack

| Layer     | Choice                                                          |
| --------- | --------------------------------------------------------------- |
| Framework | Next.js (App Router, TypeScript, Tailwind CSS)                  |
| Database  | PostgreSQL (e.g. Neon) via Prisma ORM                           |

## Getting started (local)

1. `npm install` (also runs `prisma generate`).
2. `cp .env.example .env` and fill in every value (see below). You need a
   Postgres database — a free Neon project works, or a local Postgres.
3. `npx prisma migrate deploy` to create the tables.
4. `npm run dev` and open <http://localhost:3000>.

Next.js reads `.env` only at server start — restart after editing it.

## Environment variables

| Variable           | Required | Description |
| ------------------ | -------- | ----------- |
| `GEMINI_API_KEY`   | Yes | Google AI Studio key used for all Gemini calls. The key's Google project must have Gemini API access (free tier or billing). |
| `DATABASE_URL`     | Yes | Postgres connection string. On Neon, use the **direct** (non-pooled) string so migrations work. |
| `NEWS_MODE`        | No  | `manual` (default) or `grounded`. `grounded` needs a Gemini tier with Google Search grounding quota. |
| `FACULTY_USERNAME` | Yes | Faculty login username. |
| `FACULTY_PASSWORD` | Yes | Faculty login password. |
| `AUTH_SECRET`      | Yes | Secret (16+ chars, long random recommended) used to sign group and faculty cookies. Changing it logs everyone out. |

## Deploy to Vercel + Neon

1. **Create the database** — in Neon, create a project and copy the
   **direct** connection string (host without `-pooler`), including
   `?sslmode=require`.
2. **Import the repo in Vercel** — New Project → import the GitHub repo and pick
   the branch to deploy. Framework preset: Next.js. Leave the build command as
   the default (`npm run build`, which runs `prisma migrate deploy && next build`).
3. **Set environment variables** in Vercel (Settings → Environment Variables):
   `GEMINI_API_KEY`, `DATABASE_URL`, `NEWS_MODE`, `FACULTY_USERNAME`,
   `FACULTY_PASSWORD`, `AUTH_SECRET`. Generate the secret with
   `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.
4. **Deploy.** The build applies migrations to Neon, then builds the app.
   Env var changes only take effect after a **redeploy**.
5. **Check:** open `/faculty/login`, sign in, create a test group from `/`.

## Importing past history (seed script)

`scripts/seed-history.ts` loads past reflections, news updates and notes into an
**existing** group (create it in the app first). Copy
`scripts/seed-data.example.json` to `scripts/seed-data.json`, set `groupSlug`,
replace the placeholder items with your real content, then run:

```bash
npm run seed:history                 # reads scripts/seed-data.json
npm run seed:history -- path/to.json # or a specific file
```

Item types: `REFLECTION` (`classSummary`, `unclearQuestion`, 3–5 `keyPoints`),
`NEWS_UPDATE` (`pastedText`, `items[]` of `source`/`summary`/`whyItMatters`/
optional `url`), `STUDENT_NOTE` (`text`). Optional ISO `createdAt` per item
(defaults to now). Rows are written exactly like the live app writes them. The
whole file is validated first; nothing is written if any item is invalid.
`DATABASE_URL` must point at the target database (it is read from `.env`).

## Limits and known limitations

- **Input caps:** reflection fields < 4000 characters each, news paste ≤ 8000,
  note ≤ 2000. Invalid JSON request bodies get HTTP 400.
- **Rate limiting is best-effort.** The Gemini routes allow 5 requests per
  minute per IP (passcode unlock and faculty login: 10/min). The limiter is
  in-memory: on Vercel each serverless instance has its own memory and
  instances are recycled, so it only stops bursts that hit the same instance.
  Use a shared store (e.g. Redis/Upstash) for a real limit.
- **No individual student accounts.** Everyone with a group's passcode is
  equivalent; entries are not attributed to individual students.
- **Grounding mode is tier-dependent** — on a free key it may return quota
  errors. Use `NEWS_MODE=manual` in that case.
- **Manual news mode is only as good as its input** — it never searches the
  web, and unverifiable URLs are stripped rather than shown.
